# Page recipe · appendix / sources

**Purpose:** keep the body clean while preserving the audit trail. The appendix
is where definitions, cohorts, and extra numbers live.

**Reader task:** verify a definition or find the source behind a body number.

## Slots

1. Title: "Definitions and sources" or the specific appendix topic.
2. Definitions: KPI name, formula, unit, source system, owner.
3. Changed definitions or restatements (if any), with the period affected.
4. Source list: report, publisher, date, URL/DOI; internal data extracts.
5. Extra tables/charts that support a body page.

## Variants

**A. Definition table** — KPI, formula, source, notes. The default.

**B. Source list** — numbered references matching in-page markers, 10–12 px,
single or two columns.

**C. Backup exhibit** — one large table or chart per appendix page, captioned
and sourced, with a pointer from the body page.

## Selection

A when metrics are contested; B when the deck cites external reports; C for
financial or technical backup. You may need two appendix pages; do not overload
one.

## Type and density

Dense but calm: 10–12 px for sources, 12–14 px for definitions. No accent
color except for the body-page pointer. Keep the same table style as the body.

## Evidence / caption

Every definition names the source system and the owner. Every external source
has a date and a URL/DOI. Restatements state the old and new value and the
period.

## Do / Don't

Do: match in-text markers exactly; include the access date for web sources;
keep the appendix order matching the body.
Don't: use the appendix to hide a miss; include unread sources; shrink text
below 9 px; use a different visual system from the body.
