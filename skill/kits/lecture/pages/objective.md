# Page recipe · objective

**Purpose:** state what the learner will be able to do after this segment and
how they will know they can.

**Reader task:** map the session to a capability they care about and see the
success check before the work starts.

## Slots

1. Kicker: segment number and topic, 10–12 px.
2. Title: "By the end you can…" or the capability itself, 32–40 px.
3. Two to four objectives, each an observable verb + object + condition
   ("compute a 95% interval from a sample of 30").
4. Success check: one sentence a learner can self-test against.
5. Optional prior-knowledge link: what this builds on, one line.

## Variants

**A. Numbered list** — 2–4 objectives stacked with numerals; success check in a
soft band at the bottom. The default.

**B. Three columns** — objectives in equal columns, each with its own one-line
check underneath. Use when the objectives are parallel and independent.

**C. Before / after** — left: what the learner cannot do yet; right: what they
will do. Use for remedial or reskilling audiences; never for an advanced group.

## Selection

A when the objectives build on each other; B when they are independent skills;
C only when the gap is the point of the session. Never list more than four
objectives — a fifth means the session is two sessions.

## Type and density

Title 32–40 px; objective 20–24 px; check 16–18 px; kicker 10–12 px. Keep one
idea per objective and no sub-bullets. The page should read in under 20 seconds.

## Evidence / caption

Objectives are commitments, not citations. If a standard or syllabus defines the
outcome, name it in the source line (for example "aligned to course outcome 3").

## Do / Don't

Do: use verbs a learner can demonstrate; state the condition and the threshold;
put the check where it is readable.
Don't: write "understand" or "know" as the only verb; use more than four items;
add an agenda disguised as objectives; promise outcomes the practice page does
not test.
