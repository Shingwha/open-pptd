# Page recipe · example

**Purpose:** show a real case worked by an expert so the learner can see the
move, not only the answer.

**Reader task:** follow the reasoning from prompt to result and notice the
decision point that makes the difference.

## Slots

1. Kicker: "EXAMPLE" plus the domain.
2. Title: the task or the lesson ("Why the unit check catches the error").
3. Prompt: the original problem, text, data, or artefact, quoted or shown
   unedited where possible.
4. The expert move: 2–4 numbered actions with the reason for each.
5. Result: the output, with the relevant part highlighted.
6. Source line: where the case comes from (book, dataset, project, date).
7. Optional annotation: one arrow or callout on the artefact at the decision
   point.

## Variants

**A. Prompt / move / result bands** — three horizontal bands, top to bottom.
The default for text or numeric cases.

**B. Naive vs expert side by side** — left: the common attempt; right: the
expert move; a one-line verdict underneath. Use when the lesson is the contrast.

**C. Annotated artefact** — a real screenshot, document, or diagram with 2–3
numbered callouts; the move is described in a narrow column. Use for tool-based
and visual work.

## Selection

A when the process is the lesson; B when the error is the lesson; C when the
artefact itself is the lesson. Never shrink a readable artefact into a column to
keep variant A.

## Type and density

Title 30–36 px; prompt 16–20 px; move steps 16–18 px; result 18–22 px; source
11–13 px. One example per page. If the example needs more than four moves, split
it into two pages or promote it to a walkthrough.

## Evidence / caption

Use a real case with a source. Simplified values are allowed and labelled
"simplified"; never invent a case that looks real. Screenshots keep their UI
chrome when the chrome is part of the task. Show units and rounding explicitly
in numeric examples.

## Do / Don't

Do: keep the prompt in its original wording; explain the decision, not only the
steps; highlight exactly the part of the result that proves the point.
Don't: retype a case from memory; polish away the difficulty that makes it a
lesson; show the answer before the move; use a stock image as the "artefact".
