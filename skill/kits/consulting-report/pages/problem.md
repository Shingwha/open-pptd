# Page recipe · problem

**Purpose:** define the decision and its boundaries before any analysis. A
consulting report fails when it answers a question the client did not ask.

**Reader task:** recognize the decision, the stakes, the constraints, and what a
good answer must contain.

## Slots

1. Title: the decision at stake ("Choose between market entry now and a
   partnership in 2027").
2. Situation: 2–3 facts that make the decision necessary, each sourced.
3. Complication: what changed or what is unknown.
4. Question: the explicit decision question and the scope boundaries.
5. Criteria: what a good answer must satisfy (cost, speed, risk, capability).
6. Owner/timing: who decides and by when.

## Variants

**A. Situation–complication–question** — three stacked bands, the question in
larger type. The classic and usually the clearest.

**B. Decision box** — a single framed question with constraints in a side
column. Use when the audience already knows the context.

**C. Issue map** — problem at the center, four boundary dimensions around it.
Use only when scope is contested.

## Selection

A for a first meeting; B for a steering committee; C when the team disagrees
about scope. Do not include a recommendation on this page.

## Type and density

Medium. Question 26–34 px; facts 15–17 px; criteria 12–14 px. Keep the number of
facts to three; the appendix carries the rest.

## Evidence / caption

Every situation fact has a source and period. The decision question is not a
citation. If the client's data is the basis, label it and state the extract
date.

## Do / Don't

Do: write the question as a choice; name the decision owner and deadline.
Don't: start with "background"; use a vague "how can we improve"; include a
market-size table before the question is agreed.
