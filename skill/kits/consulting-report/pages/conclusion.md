# Page recipe · conclusion

**Purpose:** put the answer on the table early. The rest of the deck exists to
make this page credible.

**Reader task:** know the recommendation and the three reasons behind it.

## Slots

1. Title: the recommendation as an imperative ("Enter through a distribution
   partnership in Q1 2027").
2. Three reasons: each a claim with a number or evidence pointer.
3. Condition/assumption: what must be true for the answer to hold.
4. Ask: the decision or resource required, with date.
5. Source line if the reasons use external data.

## Variants

**A. Answer + three reasons** — the answer in 30–36 px across the top; three
numbered reasons below. The default.

**B. Answer + option map** — one sentence answer on the left; the three options
and their verdicts on the right. Use when the audience saw the options first.

**C. One-page memo** — a 20–24 px paragraph with the answer and conditions,
then three bullets. Use for a written pre-read.

## Selection

A for a live meeting; B after an options page; C for a pre-read or a short
deck. Do not repeat the problem page's question verbatim; answer it.

## Type and density

Medium. Answer 30–36 px bold; reasons 16–18 px; evidence pointers 11–12 px.
Leave the ask in its own band so it is not read as a fourth reason.

## Evidence / caption

Each reason points to the exhibit that proves it (`Exhibit 2`, page number).
If the answer rests on an estimate, state the method and range on this page or
point to the appendix.

## Do / Don't

Do: make the recommendation falsifiable; state the condition; use the client's
language.
Don't: hedge with "consider", "explore", or "potentially"; give five reasons;
hide the ask.
