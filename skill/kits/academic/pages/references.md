# Page recipe · references

**Purpose:** make the evidence trail auditable. This page is not decoration and
not a place to dump every citation.

**Reader task:** find the source behind a claim quickly.

## Slots

1. Title: "References" or "Selected references".
2. Entries: one citation style, consistent; 12–16 px; hanging indent if the
   layout supports it; numbered if in-text markers are numeric.
3. Grouping: by theme or by first appearance if the list is long; no cards.
4. Access note (optional): data/code availability, DOI/URL column.

## Variants

**A. Single column** — 8–12 entries; the safe default. Use a narrow measure
(≤70 characters per line).

**B. Two columns** — 12–20 entries; split at a logical point, not mid-entry.
Keep the same font size in both columns.

**C. Split selected/full** — selected references on the slide; a note that the
full list is in the paper or appendix. Use only when the deck cites far more
than fits.

## Selection

A for a defense with a short reference list; B for a conference deck with a
broad literature base; C when the paper's full bibliography is the source of
truth. Never shrink below 11 px to fit more entries.

## Type and density

Medium-high density is acceptable here, but keep the hierarchy flat: no bold
titles inside entries, no colored links on every line. Use one accent only for
the DOI/URL if needed.

## Evidence / caption

Every in-text author–year or numeric marker must appear here. Every entry must
be real and checkable; do not include a citation you did not verify. Keep the
source's DOI/URL where available.

## Do / Don't

Do: use one style (APA, Chicago, IEEE, or the venue's); keep author order and
year exact; include the accessed date for web sources when the style requires
it.
Don't: pad the list with unread papers; mix styles; use a wall of 9 px text;
put references in a decorative card grid.
