# open-pptd v3 重构方案（定稿）

> 状态：已定稿并完成 P0–P2 实施 ｜ 日期：2026-08 ｜ 范围：**纯工程重构**（引擎抽包 + Web/底层解耦 + 代码统一清理 + 校验器）
> 取代：`docs/v3-architecture.md`（SaaS 草案）、旧 `docs/v3.md`（桌面化草案），均已废弃删除。

---

## 0. 范围声明

**做什么**：把引擎从 `editor/` 前端目录中抽出来形成独立分层，封装渲染/导出管线，收口重复实现，固化校验层，让架构清晰、可扩展、依赖方向可被 CI 强制。

**不做什么**（本次明确排除，避免范围漂移）：

- 不做 AI 生成引擎（LLM 生成流水线、对话页）
- 不做服务化/SaaS（用户体系、认证计费、Docker 部署、存储抽象）
- 不做 Electron 桌面化、不做 Node 原生渲染器（renderer 仍输出 DOM）
- 不改 PPTD 格式契约、不改 writer 导出结果（行为零变化为底线）

## 1. 现状诊断（重构依据）

1. **引擎寄居 UI 目录**：`editor/core|renderer|writer|types` 是纯引擎，`lib/`、`bin/` 反向 import "前端目录"深处，引擎不是独立可复用单元。
2. **渲染链路是重机械**：渲染只在浏览器里，CLI `render` 靠临时 server + 无头 Chrome + 自研 MiniWebSocket + CDP 共 500 行（`lib/pptd-render.js`）才能截图。
3. **server 一文件四角色**：静态服务 + `/api/save` + SSE + 画廊扫描挤在 `lib/editor-server.js`；SSE 为 800ms 全目录轮询。
4. **重复实现漂移**：XML 转义 4 份；base64/bytes 转换 4 处；图片 src 收集遍历 4 遍；`lib/gallery.js` 正则解析 YAML 与 js-yaml 全解析并存；960×540 硬编码 3 处（其中 `writer/background.js:18` 忽略 `deck.size`，非标准尺寸背景图算错，**现存 bug**）。
5. **"预览=导出"靠口头约定**：10+ 文件头注释写"与 writer 一致"，无契约测试强制；`types/` 同时 import renderer 与 writer，是双向耦合枢纽。
6. **编辑器状态层脆弱**：全局可变 state + 手动 `beginChange` 配对；`api.bind` 延迟注入绕循环依赖；渲染层把实测高度写回模型污染 dirty 判定（本轮只收口不 redesign，见 §6 P2）。

**保留的资产**：PPTD 单一契约、`types/registry.js` 注册表扩展模式、零依赖纯 ESM、分层测试体系（npm test 回归 + E2E）。

## 2. 目标与原则

- **G1 引擎独立**：model / writer / renderer 成为目录边界清晰的独立层，浏览器与 Node 双端复用，零第三方依赖。
- **G2 依赖方向可强制**：`model ← writer/renderer ← editor(UI)/server/cli`，`tests/regression/dep-graph.mjs` 静态扫描进 CI，防解耦退化。
- **G3 单一事实来源**：同一逻辑只存在一份（转义、编解码、遍历、页面尺寸、YAML 解析），重复实现全部收口。
- **G4 行为零变化**：除明确列出的 bug 修复外，渲染结果与导出字节不变；npm test 全量回归守门。

设计原则：

1. PPTD 仍是唯一跨层契约（YAML 文本），预览=导出原则不变。
2. 保持零依赖、无构建步骤、纯 ESM 相对导入；不引入 npm workspaces。
3. 扩展点沿用注册表模式（元素类型、校验规则、导出器），新增能力 = 注册新模块。
4. 每阶段可发布、可回退、测试守门；不为重构而重构。

依赖规则（`tests/regression/dep-graph.mjs` 强制）：

- `model` 不得 import 任何兄弟包；`writer`/`renderer` 只允许 import `model`。
- `server`/`cli` 可 import `model`/`writer`/`renderer`；`editor` 可 import `model`/`writer`/`renderer`，**不得** import `server`/`cli`。
- `renderer/headless` 是 renderer 内唯一允许出现 Node API 的子目录（边界注释 + 扫描白名单）。
- 跨环境代码（model/writer/renderer 非 headless 部分）禁止出现 `window`/`document`/`fs` 等环境全局（headless 与 editor 除外）。

## 4. 关键设计点

### 4.1 类型注册表解耦（最核心的枢纽拆分）

现状：`editor/types/*.js` 每个文件同时 import renderer 的 `render` 和 writer 的 `toXml`，任何一端抽包都会被拉住。

方案：

- `packages/model/registry.js` 只保留契约：`registerType(type, partial)`、`getType(type)`，支持**分片注册**（render / toXml / props / quickbar / menu / create 可分别挂）。
- render 分片注册移到 `packages/renderer/types/<type>.js`（import 同包 renderer 实现）。
- toXml 分片注册移到 `packages/writer/types/<type>.js`（import 同包 writer 实现）。
- UI 分片（props 面板/quickbar/menu/create）留在 `editor/types/<type>.js`。
- 装配方按需引入：编辑器 `main.js` 引全部；CLI export 只引 writer 分片；渲染截图只引 renderer 分片。

效果：writer 不再被 UI 依赖穿透，纯 Node 导出链路不带任何 DOM 代码。

### 4.2 渲染链路封装（保留浏览器渲染，链路收干净）

维持"DOM 是唯一渲染目标"的决策，把 500 行重机械拆成边界清晰的模块：

- `renderer/headless/browser.js`：Chrome/Edge 候选路径发现（含 `SMOKE_CHROME`）。
- `renderer/headless/ws.js`：MiniWebSocket（保留，附 undici 句柄泄漏的实测注释）。
- `renderer/headless/cdp.js`：CDP 会话与 `Page.captureScreenshot` 循环。
- `renderer/headless/shoot.js`：编排 = 临时 server + `?shot=1` 页面 + 截图落盘。
- `packages/cli/render.js` 只做参数处理，调 `shoot()`。

`editor/app/shot.js` 的 `window.__pptdShot` 钩子**正式化为文档化契约**（tests 与 headless 依赖），写入文件头注释与 docs。

### 4.3 server 拆分与 CLI 收口

- `editor-server.js` 四角色拆为 `packages/server/` 五文件（见 §3），对外接口（`createServer/startServer` 签名、端点、SSE 协议）不变；`/events` 指纹轮询实现不变（优化轮询开销列为可做项，不强制）。
- `bin/open-pptd.js` 内联的 fonts 下载逻辑（并发池、源降级链）迁入 `packages/cli/fonts.js`，bin 变纯分发壳。
- `lib/gallery.js` 迁入 `packages/server/gallery.js`，YAML 解析从正则改为 js-yaml 全解析（与 model 同源），消除双解析漂移。

### 4.4 校验器（model 层新能力）

`packages/model/validate.js`：`validateDeck(deck) → { errors, warnings, perPage }`，规则注册表模式（新规则 = 注册新函数）。维度：

- schema：字段类型/必填/数值边界/枚举（对齐 pptd.md 契约）
- token 引用：`$key` 必须命中 theme；fontFamily 命中注册表或声明资源
- 资源引用：图片 src 存在、iconName 在图标库
- 几何启发式：元素越界、文本溢出估算、重叠遮挡
- 对比度：文本 vs 背景 WCAG 相对亮度比（warning 级）

消费端：`open-pptd check <deck.pptd>` 命令；`export` 前置闸门（error 阻断、warning 报告）；编辑器实时校验留为后续增强（UI 挂钩点预留，本轮不做）。

## 6. 分阶段路线与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 引擎抽包** | `editor/core+types` → `packages/model`（含注册表拆分 §4.1）、`editor/writer` → `packages/writer`、`editor/renderer` → `packages/renderer`；纯搬移 + import 修正；新增 `tests/regression/dep-graph.mjs` | npm test 全量回归全绿；CLI（export/render/serve/gallery/fonts）行为不变；编辑器功能不变 |
| **P1 服务与 CLI 收口** | server 拆分（§4.3）、headless 封装（§4.2）、fonts 逻辑迁 CLI、gallery 改名与 YAML 统一；清理清单 §5 #4（bug 修复）#5 #7 #8 #9 | 全量回归 + e2e（test:incremental/test:render）全绿；非标准尺寸 deck 背景导出正确（新增用例） |
| **P2 代码收口 + 校验器** | 清理清单 §5 #1 #2 #3 #6 #10 #11；`model/validate.js` + `open-pptd check` + export 前置闸门 | 重复实现扫描为零；`check` 对 examples 全量通过；坏 deck 被 export 闸门拦截（新增用例） |

- 每阶段独立可发布；P0 风险最低（纯搬移）先行，P2 落在新边界上收益最大。
- 守门：`npm test`（run-all 全量回归）+ e2e + 新增 dep-graph 与契约测试，随阶段同步扩展。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 纯搬移引入 import 遗漏，浏览器/Node 双端其一炸掉 | P0 每步跑 run-all + e2e；dep-graph 测试同阶段落地 |
| 注册表分片注册改变装配时序（类型未注册即渲染） | 装配根统一 `registerAll()`；getType 未命中时报错信息带"是否漏引分片"提示 |
| 环境全局泄漏（DOM API 进 model/writer 炸 CLI） | dep-graph 扫描含环境全局白名单检查；headless 子目录单列 |
| 修 `writer/background.js` 尺寸 bug 改变存量导出 | 该路径本就算错，按 bug 修复处理；新增非标准尺寸回归用例锁行为 |
| 大包文件（chart.js 1454 行、preset-geometry.data.js 1513 行）随搬移被顺手改坏 | 生成数据文件只动路径不动内容；chart 双引擎合并**不在本轮范围**（单独立项评估） |

## 8. 一句话总结

**v3 = 把引擎从编辑器目录里抽出来成为 `packages/` 下依赖方向可被 CI 强制的独立层，渲染/导出/服务/CLI 四条管线各自收口成单一事实来源，再用校验器把人工审查经验固化成质量闸门——不加新功能，只让架构配得上已有的引擎质量。**
